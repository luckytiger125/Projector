# 阶段四到七实施说明：把老弹层逐个换成组件

给实现的人看。先读总方案 `2026-11-frontend-vite.md`（第 2、3、4、6、7、9、10 节）和 `2026-11-frontend-vite-stage3.md`（“不许做的事”“怎么跑和怎么测”“汇报要写什么”三节在这里同样适用，不重复）。一次只做派给你的那一个阶段，做完停下来汇报。

## 现状（阶段三做完以后）

- 登录、外壳、值班板、对话已经是 Preact 组件：`web/src/features/{auth,shell,home,chat}`，状态在 `web/src/stores/`，路由在 `web/src/router.ts`。
- 文件库、技能、用量、手机二维码、头像、改密码、分区设置还在 `web/src/legacy/app.js`；管理后台在 `legacy/admin.js`；知识库在 `legacy/kb.js`。它们靠 `legacy/bridge.ts` 读写新状态，静态 DOM 还在 `web/index.html` 里，样式还在 `styles/base.css`、`styles/almanac.css`。
- 路由到老弹层的同步在 `stores/overlays.ts`。
- 新组件的样式都限定在 `.px` 下（`styles/px.css`），因为老弹层还在用 `.btn`、`.card`、`.dialog` 这些同名类。

## 每个阶段的共同要求

1. **外观按样稿重做**：弹层用统一骨架（`docs/design/mock.css` 里的 `.veil / .sheet / .sheet-head / .sheet-bar / .sheet-body / .pane`），列表用账页式表格（`.ledger`），手机端全屏、带返回、表格变成一行一条且**不丢列**。骨架做成共用组件（阶段四建，后面复用）。样稿没覆盖到的界面，照同一套变量和写法自己延伸，不要回头用老样式。
2. **功能和文字不变**：老代码里这个弹层的每一个操作、每一句提示都要在新组件里有，文字原样搬。开工前先把老代码里这一块的功能列成清单，写进汇报，逐项标实测结果。
3. **删干净**：迁完的那部分老代码、`index.html` 里的静态 DOM、`base.css` / `almanac.css` 里的规则、`bridge.ts` 里不再需要的全局都删掉。一块 DOM 只有一个主人。
4. **网址**：弹层内部的位置写进网址（见各阶段），直接打开、刷新、前进后退都对；关闭弹层回到背景页。
5. **状态**放 store，组件不直接 `fetch`；改动类请求带 `Authorization` 头；用户内容渲染前必须净化或转义。
6. 每阶段结束 `npm run check`、`npm run build`、`pytest` 全过，起 18282 实例在桌面宽度和 380 像素各实测一遍。
   - 预览面板里动画时钟可能不走，弹层会停在透明的第一帧。截图前先在页面里执行 `document.getAnimations().forEach(a => { try { a.finish() } catch {} })`。
   - 种子数据不够测的（技能、知识库笔记、超过一页的列表、docx/xlsx 文件），自己通过接口或直接往实例的数据目录里造，造数据的脚本放草稿目录，不要放进仓库。

## 阶段四：文件

范围：文件库弹层（我的文件、公共文件库、搜索、预览、回收站）、上传和拖拽（含上传到公共文件库的确认、同名文件处理）、引用到对话、整理进知识库的入口、本机文件夹同步（桌面壳里“添加本机文件夹”“同步回本机”，浏览器里的逐个下载提示）。

- 新增 `stores/files.ts`、`features/files/`，以及共用的弹层骨架组件。
- 网址：`/files?path=…`（当前目录）、`/files/trash`；预览中的文件也写进网址（查询参数），刷新后还在。
- 预览：文本、图片、Markdown、docx、xlsx（含 GBK 编码的老 xls）、太大的文件和二进制文件的提示。docx / xlsx 仍然动态加载，不进首屏。**这一项必须用真实文件实测**，自己生成测试文件。
- 桌面壳相关的功能在浏览器里测不了，代码照老逻辑搬，汇报里列出来留给用户在桌面软件上验证。
- 顺带修阶段三留下的两处外观问题：
  - 对话左侧时间线里名字较长时（如“测试管理员”）会换行，改成单行省略。
  - 回复里的 Markdown 表格带了老样式的单元格边框，按样稿改成只有横线。

## 阶段五：技能和账户

范围：我的技能、技能详情、取出技能、提交技能和提交新版本；我的用量（本月 / 上月、按模型和按会话的表）；在手机上打开（二维码）；更换头像；修改密码；会话的分区选择；主题切换提示。

- 网址：`/skills`、`/skills/{name}`、`/usage`、`/mobile`。从列表点进详情要更新网址。
- 这一阶段做完，`legacy/app.js` 应该可以整个删掉。

## 阶段六：知识库

范围：`legacy/kb.js` 的全部：首页、笔记列表和搜索、分区筛选、笔记阅读、双链和“提到这条的笔记”、新建 / 修改 / 删除、文件卡片和过时提示、关系图谱、整理重要文件、沉淀经验、未保存时的离开确认。

- 开工前把 `kb.js` 从头到尾读完。
- 网址：`/kb`、`/kb/notes?note=…`、`/kb/graph`。
- 关系图谱的布局算法照搬，只换外观；节点多时拖动和缩放要流畅。
- 笔记正文渲染必须净化；双链的解析规则和老代码一致，补单元测试。

## 阶段七：管理后台和收尾

范围：`legacy/admin.js` 的八个页签（用户、聊天记录、技能库、待审核、文件记录、用量、分区、设置）。

- 开工前把 `admin.js` 从头到尾读完。
- 网址：`/admin/{tab}`；聊天记录里点开某个会话也写进网址。非管理员打开 `/admin/*` 回首页。
- 收尾：删除 `web/src/legacy/` 整个目录、`web/plugins/legacy.ts`、`stores/overlays.ts` 里为老弹层做的同步、`styles/base.css`、`styles/almanac.css`；`.px` 这层限定可以去掉（去掉后全站回归一遍）。删完以后搜一遍确认没有残留的 `window.` 全局依赖。
- 深色主题：老版本的“深色”实际上没有视觉效果。这一阶段不新增深色配色，保持现状，在汇报里记一笔即可。
