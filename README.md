# Projector：局域网网页 + 桌面软件，远程指挥台式机上的 Claude

```
台式机 Windows
 ├─ server.py                     中心服务：账号、多会话、权限确认、技能库，调用 Claude Code（工作目录 D:\）
 │  server.py 只做组装；业务拆在：
 │  events.py（SSE 推送）/ approvals.py（权限确认和提问）/ runner.py（调用 Claude Code）/
 │  sessions_api.py（会话）/ auth_api.py（登录和账号）
 │  其余：store.py / files_api.py / skills_api.py / kb.py / usage.py / sections.py / approval_mcp.py
 └─ 局域网：http://台式机名:8080（桌面软件自动发现）
        ▲
        │
同事的电脑：Projector 桌面软件，或浏览器打开网页端
```

## 功能

- **账号**：管理员在台式机上给每个人建账号，同事只能登录、不能注册。每个人只看得到自己的会话、工作区和确认请求；管理员能按人查看所有聊天记录（只读）。
- **会话**：多个会话、回复逐字输出、显示 Claude 读了哪些文件和做了哪些操作、可以中途停止。“完整过程”可以看 Claude Code 保存的每一步思考和工具调用。
- **工作文件夹**：每个会话可以选一个文件夹（顶栏 📂），Claude 就在那里干活，不同会话互不干扰。只能在会话开始前选。
- **📎 引用文件**：从文件库（D 盘）选文件或文件夹，或在输入框里打 `@`，作为标签随消息发给 Claude。
- **工作区**：每个人上传的本机文件、Claude 取出来修改的技能都放在 `D:\Projector工作区\<显示名(用户名)>\<日期 会话标题>\`，在 D 盘里就能直接找到。网页上只有本人能进自己的那份，管理员也进不去（见“文件可见范围”）；会话改名后文件夹名不变。可以用环境变量 `WORKSPACE_ROOT` 改位置。
- **💻 本机文件**：把同事自己电脑上的文件交给 Claude。文件上传到台式机上这个人的工作区（别人看不到），Claude 在那里处理，用的是台式机上的技能。
  - 桌面软件里“添加本机文件夹”：处理完点“查看改动 / 同步回本机”，把新增和修改的文件写回原文件夹；被覆盖的原文件先备份到那里的 `.projector备份` 文件夹。
  - 也可以直接把文件拖进窗口；浏览器里处理结果逐个下载。
- **🧩 技能**：每个人都能提交 skill（含 `SKILL.md` 的文件夹或 zip），管理员审核后入库，再分配给指定的人或所有人。输入框旁的 🧩 只列出分配给自己的技能，选中后 Claude 会用它完成这次任务；不选时 Claude 也会在已分配的技能里自动判断。
  - **版本**：每次审核通过记成一个新版本（v1、v2……）。技能详情里能看到每个版本是谁改的、改了什么、改了哪些文件；管理员可以回滚。
  - **在对话里改技能**：直接跟 Claude 说“帮我把周报技能加上下周计划”或“帮我做一个检查合同的技能”。Claude 会用 `skill_checkout` 把技能取到你的工作区、改好后用 `skill_submit` 提交新版本，管理员审核通过才生效。也可以在技能详情里点“在对话里修改”或“上传新版本”。
- **📱 手机**：手机连同一个 Wi-Fi，在个人菜单里点“在手机上打开”扫二维码即可；iPhone 用 Safari“添加到主屏幕”后像 App 一样全屏打开，安卓用 Chrome“添加到主屏幕”。手机上不能“同步回本机”和“用本机程序打开”。
- **📁 文件库管理**：文件面板分“我的文件”（自己的工作区，只有自己能看，默认打开）和“公共文件库”（所有人可见）两块。所有人都能在公共文件库里上传文件和文件夹（也能直接拖进去，上传前会提示“所有人都能看到”）、新建文件夹、改名、删除。删除和被覆盖的文件进 `D:\Projector工作区\回收站`，保留 30 天，可以在网页里恢复；每一步操作都记在“管理后台 → 文件记录”。Projector 程序自己的文件夹和工作区根目录不能改。
- **📁 文件预览**：浏览、搜索 D 盘和自己的工作区。图片、PDF、音视频、文本（自动识别 GBK）、Markdown、Word、Excel 直接预览；PPT、老版 Word、WPS 需要台式机装 [LibreOffice](https://zh-cn.libreoffice.org/download/download/)；预览不了的，桌面软件里可以“用本机程序打开”。Claude 回复里的路径也能直接点开。
- **💬 Claude 提问卡片**：Claude 需要你拿主意时（用哪个模板、处理哪几个月……），输入框上方会弹出选项卡片，像 Claude 桌面端那样点选即可：按数字键选、回车提交，可以多选、填“其他”、加备注，也可以“跳过，让 Claude 自己决定”。问答会留在聊天记录里。
- **🗂 分区**：团队统一的分类（合同、客户……），见下面一节。
- **📊 用量**：每个人能看自己的 token 用量，管理员看全队，见下面一节。
- **📖 知识库**：见下面一节。

## 知识库

把团队的经验和重要文件串起来，Claude 回答问题前会先查这里。

- **存在哪**：`D:\知识库`，就是一堆 Markdown 笔记，格式和 [Obsidian](https://obsidian.md) 一样，想看关系图也可以直接用 Obsidian 打开这个文件夹（日常在网页里用就行）。可以用环境变量 `KB_ROOT` 改位置。
- **三类笔记**：
  - **经验**：做成过一件事以后的背景、做法、用到的文件、踩过的坑。在 Claude 的回答下面点 **“沉淀成经验”**，Claude 会整理成笔记（有相关的旧笔记就合并进去）。
  - **文件卡片**：重要文件或文件夹的摘要、关键信息（金额、日期、对方……）和位置。在文件库里选中文件或文件夹点 **“整理进知识库”**，Claude 会新开一个会话读文件、写卡片。原文件改过后，卡片会提示“可能过时”，点“让 Claude 更新”即可；文件库预览文件时也会提示“知识库里有这份文件的卡片”。
  - **主题**：项目、客户、供应商、产品等，把相关的经验和卡片连在一起。
- **链接**：笔记里写 `[[笔记名]]` 就连上了，链接到还没写的笔记也可以（虚线显示，点一下就能新建）。Claude 回答里的 `[[笔记名]]` 也能直接点开。笔记改名时，其他笔记里的链接会跟着改。
- **网页里**：侧栏“知识库”或顶栏 📖。首页看统计、最近更新、常被提到的主题、需要更新的卡片；“笔记”里按类型和标签筛选、全文搜索、阅读、编辑（输入 `[[` 会提示笔记名）；“关系图谱”看笔记之间怎么连在一起。
- **Claude 怎么用**：遇到和公司业务、项目、客户、以前做过的事有关的问题，会先用 `kb_search` 查；用 `kb_write` 写（只在你要求时写，自动记作者）；用 `read_document` 读 Word、Excel、PPT、PDF 的文字（老版 .doc/.xls 需要 LibreOffice）。
- **改错了能恢复**：每次修改都留历史版本（网页里“历史”可以恢复）；删除的笔记进回收站。所有人都能看、能改知识库，修改记在“管理后台 → 文件记录”。
- **注意**：知识库对所有人可见，不要把薪资、身份证号、银行卡号这类内容写进去。

## 分区

分区是整个团队共用的分类，只用来整理和筛选，**不是权限边界**：别人的会话照样看不到。

- **谁能建**：管理员在“管理后台 → 分区”里新建、改名、排序、归档和恢复；归档后的分区不能再选，但已有的会话和笔记仍显示它的名字。分区改名时，知识库笔记里记的分区名会一起改。
- **会话**：新建会话时选分区（不选就用上次选的），侧栏可以按分区筛选，也可以事后给会话改分区。
- **笔记**：知识库笔记在 frontmatter 里记 `section`，可以按分区筛选或筛“未分类”。Claude 在会话里写笔记时，笔记自动归到该会话的分区。

## 用量统计

每一轮对话结束后，服务端把 Claude Code 返回的 token 数（输入、输出、缓存读、缓存写）和费用估算按人、按模型记进数据库。

- 个人菜单 → “我的用量”：默认看本月，可选日期范围或全部；有按天汇总、按模型汇总和最近几轮。
- “管理后台 → 用量”：全队汇总，外加按人排行。
- token 是模型调用量，不等于套餐额度；费用只是估算，第三方模型可能没有费用数据。升级前的对话没有记录。

## 文档缓存

`read_document` 和知识库读文档时，Word、Excel、PPT、PDF 等解析成文字的结果会缓存，同一份文件没改过就不用重复解析。

- 缓存键是文件路径、大小、修改时间和提取器版本；文件一改就自动失效。解析出来的 Markdown 存在 `data/doc_cache`，内存里另有一层小缓存。
- 提取不出文字的扫描件会记成“无文字”状态，不会反复解析。
- 超过 2 GB 时，按最久没用的先删；清理每 7 天自动做一次，也能在管理员接口手动触发。
- 管理员接口：`GET /api/admin/doc-cache` 看条数、体积和命中次数，`POST /api/admin/doc-cache/prune` 立即清理。缓存出任何问题只写日志、不影响读文档。

## 权限

管理员在“管理后台 → 设置”里选权限档位，对所有人生效：

| 档位 | 自动执行 | 要确认 |
|---|---|---|
| **标准（默认）** | 读文件、改文件、运行 python / unzip / tar 等所有命令 | 删除、移动、格式化、改系统、强制推送等危险命令（名单可改） |
| 严格 | 读文件、ls / cat 等只读命令、管理员加的白名单命令 | 其他所有操作；改文件也要确认 |
| 完全放行 | 全部，不再询问 | 无。管理员在“用户”里按人开通 |

- 确认请求只推送给会话主人（和管理员）。30 分钟没人确认就自动拒绝。
- 标准档靠命令开头匹配：写 `rm` 能拦住 `rm -rf 文件夹`，但用 python 脚本删文件这类间接操作拦不住。
- **隔离是软隔离**：所有人的 Claude 都以台式机上同一个 Windows 账号运行。界面、记录、工作区各管各的，Claude 用文件工具或命令去碰别人的工作区和系统数据会被直接拦下（三个档位都一样，不弹确认）；但这是按路径和命令文字做的检查，不是系统级的权限，上限见下面“文件可见范围”。
- **技能里的脚本**会在台式机上以完整权限运行，管理员审核时要看代码（审核页会标出脚本文件和这次改动的文件）。
- **排查**：每个会话的 Claude 报错写在 `data/logs/claude_<会话id>.log`，权限确认工具的记录在 `data/logs/approval_mcp.log`。如果聊天里提示“权限确认通道出了故障”，重发一次通常就好，反复出现就看这两个日志。

## 文件可见范围

| 位置 | 谁能在网页上看到 | 谁的 Claude 能读 |
|---|---|---|
| 公共文件库（D 盘，工作区以外的部分） | 所有人 | 所有人的 |
| 个人工作区 `D:\Projector工作区\<显示名(用户名)>\`（对话里上传的文件、“我的文件”） | 只有本人；**管理员也不能**浏览、搜索、预览、下载、改名、删除 | 只有本人的 |
| 回收站 | 本人看到自己删的和自己工作区里被删的；管理员能看到所有条目，但别人的个人文件只显示“是谁的、多大”，不能预览、不能恢复，只能彻底删除 | 都不能 |
| 聊天记录 | 本人；管理员可以只读查看所有人的（聊天里出现过的文件名、Claude 引用的内容会在记录里） | — |

- 个人文件（工资、合同、证件等）放“我的文件”或在对话里上传；**放进公共文件库的文件所有人都能看到**，以前已经放进去的不会自动挪走，需要自己移到“我的文件”。
- 管理后台的“用户”里只显示每个人工作区占用的空间和文件数，没有进入的入口。
- Claude 这一侧靠一个每次工具调用前都会执行的检查（`guard.py`，Claude Code 的 PreToolUse 钩子）：读写路径、命令里出现别人的工作区、工作区根目录、回收站或系统数据，就直接拒绝；在工作区的上级目录（比如整个 D 盘）做 `grep -r`、`find` 这类递归扫描也会被拒绝，Claude 会改为指定具体文件夹或用自带的搜索工具（搜索工具会尽量跳过别人的工作区）。检查脚本出错时按拒绝处理：如果所有操作都提示“隔离检查出错”，看 `data/logs/claude_<会话id>.log`。

**这套隔离的上限**（它管的是“网页和 Claude”这两个入口，不是 Windows 的文件权限）：

- 能直接操作那台台式机的人（坐在电脑前、远程桌面、共享了 D 盘），可以在磁盘上直接打开任何人的工作区。需要防这一层，要用 Windows 账号和文件夹权限，Projector 不管。
- 对 Claude 的检查是看路径和命令的文字，绕得过去：让 Claude 写脚本在运行时拼出路径、用变量或编码把路径藏起来、通过符号链接或短文件名访问，都拦不住；技能里的脚本同理。它能防的是“无意中翻到”和“随口让 Claude 去看别人的文件”，防不住有技术能力、存心要看的人。
- 默认工作区就在文件库（D 盘）里面。想让两者彻底分开，可以用 `WORKSPACE_ROOT` 把工作区放到文件库以外的盘或文件夹。

## 运行方式（cli / sdk）

服务端调用 Claude Code 有两种方式，用一个开关切换，**默认是 `cli`**：

| 运行方式 | 做法 | 状态 |
|---|---|---|
| `cli`（默认） | 每一轮对话起一个 `claude -p` 进程，结束就退出，下一轮靠 `--resume` 接上 | 一直在用的方式 |
| `sdk` | 用 [Claude Agent SDK](https://github.com/anthropics/claude-agent-sdk-python) 给每个会话保持一个常驻的 `claude` 进程，同一会话后面的消息不用再冷启动 | **新加的，还没在 Windows 和 DeepSeek 上验证过**，启用前先按下面的清单试一遍 |

两种方式下界面、权限三档、文件隔离、知识库和技能工具、排队和并发上限、用量统计都一样，会话也通用：在一种方式下聊过的会话，切到另一种能接着聊。

**启用 `sdk`：**

1. 装依赖（可选依赖，不装不影响 `cli`）：在服务文件夹里运行 `.venv\Scripts\pip install -r requirements-sdk.txt`。这个包自带一份约 300 MB 的 Claude Code，下载要等一会儿。
2. 台式机上的 Claude Code 必须是**原生的 `claude.exe`**（官方安装脚本 `irm https://claude.ai/install.ps1 | iex` 装出来的，在 `%USERPROFILE%\.local\bin\claude.exe`）。用 npm 装的是 `claude.cmd`，SDK 出于安全原因拒绝运行它；这种情况下服务会依次去找 `claude.exe`、SDK 自带的那一份，都没有就报错并提示怎么办。也可以在 `config.bat` 里把 `CLAUDE_BIN` 直接指到 `claude.exe`。
3. 打开开关，二选一：
   - 在 `config.bat` 里加 `set "RUNNER_MODE=sdk"`，重启服务；
   - 或者不重启：在“管理后台 → 设置 → 运行方式”里选“常驻会话（试用）”。这里的设置优先于环境变量，对下一条消息立即生效；用不了的时候卡片下面会写原因。
4. 启动时控制台会打印“运行方式：sdk（常驻会话）”；不可用时后面会跟原因。`GET /api/admin/settings` 里的 `sdk_available`、`sdk_error`、`sdk_clients`（当前常驻进程数）也能看到状态。

**切回 `cli`：** 出任何问题都可以随时切回，不丢会话。

- 在“管理后台 → 设置 → 运行方式”里选回“每轮启动（默认）”，空闲的常驻进程会立刻关掉；
- 或者把 `config.bat` 里的 `RUNNER_MODE` 去掉（或改成 `cli`）再重启。注意：如果之前在设置页里选过“常驻会话”，设置页优先，要先在设置页里改回来。
- `sdk` 方式用不了的时候（包没装、找不到 `claude.exe`、启动失败），发消息会直接得到一条写明原因和“切回 cli”的错误，不会卡住。

**常驻进程怎么管：**

- 每个会话最多一个 `claude` 进程，空闲 10 分钟后自动关掉（`SDK_IDLE_SECONDS`，或设置页里的空闲时间，30~86400 秒），下次发消息时重新启动并接上上下文。
- 常驻进程总数默认不超过 8 个（`SDK_MAX_CLIENTS`），超了先关最久没用的空闲进程。同时在跑的任务数仍由“同时运行的任务数”（`MAX_CONCURRENT`）限制。
- 点“停止”、任务超时、删除会话、改了这个会话的权限或引用了新的文件夹、服务退出时，对应的进程会被关掉（Windows 上连同它的子进程一起结束）。
- `claude` 进程自己异常退出时，正在进行的那一轮按出错收尾，下一条消息会自动重新启动。
- 权限确认和 Claude 的提问在 `sdk` 方式下不经过 `approval_mcp.py`，由服务进程直接处理（所以聊天里不会再出现“权限确认通道出了故障”的提示）；文件隔离的检查也在服务进程里做（规则和 `guard.py` 相同，出错按拒绝处理）。知识库、技能、读文档这些工具仍由 `approval_mcp.py` 提供。

**在 Windows 台式机上启用前的验证清单**（建议找一个测试账号，先用官方模型或 DeepSeek 各走一遍；每一项不对就切回 `cli` 并把 `data/logs/claude_<会话id>.log` 留下）：

1. `pip install -r requirements-sdk.txt` 能装上；启动时打印“运行方式：sdk（常驻会话）”且后面没有“不可用”。
2. 发第一条消息能正常回答；同一会话再发一条，明显比第一条起得快。
3. 回答是逐字出来的，思考和工具步骤显示正常，中文不乱码。
4. 标准档：让 Claude 删一个测试文件（`rm`），弹出确认卡片；分别试同意、拒绝各一次。
5. 严格档：让 Claude 改一个文件，弹确认。完全放行档：同样的操作不弹确认。
6. 文件隔离：让 Claude 读另一个账号工作区里的文件、用 `cat` 读、在 D 盘根目录 `grep -r`，三个档位下都被拒绝（重点试完全放行档）。
7. 让 Claude “用选项问我一个问题”：弹出选项卡片，回答一次、跳过一次。
8. 知识库搜索（“在知识库里搜一下 XX”）、列出技能、用 `read_document` 读一个 Word 或 PDF，都能用。
9. 跑一个长任务，中途点“停止”：界面显示“已停止”；任务管理器里没有残留的 `claude.exe`、`node.exe`、`bash.exe`，也没有多出来的 `python.exe`。之后再发消息能接着聊。
10. 放着不动超过空闲时间（可以先把 `sdk_idle_seconds` 调成 60）：任务管理器里那个 `claude.exe` 消失；再发消息能接上之前的上下文。
11. 关掉服务窗口：没有残留的 `claude.exe`。
12. 找一个以前在 `cli` 方式下聊过的会话，切到 `sdk` 后接着聊，Claude 记得之前的内容；再切回 `cli` 也记得。
13. 同时开几个会话发消息，超过并发上限的会排队；“用量”页里这些对话的 token 和费用有记录。
14. 用 DeepSeek 时把 2~8 再走一遍。
15. 如果服务不是从 `start.bat` 的窗口启动的（比如计划任务、`pythonw`），看每次启动 `claude` 时会不会闪出黑色的命令行窗口。

## 在台式机上安装

1. 安装 [Python 3.10+](https://www.python.org/downloads/)，安装时勾选 “Add python.exe to PATH”。
2. 安装 Claude Code 并完成登录或配置（用 DeepSeek 的话，按 DeepSeek 文档设置 `ANTHROPIC_BASE_URL` 等环境变量，也可以写进 `config.bat`）。在命令行里运行 `claude -p "你好"`，能正常回答就说明可以用了。服务端找 `claude` 时会先看 PATH，找不到再去常用安装位置（官方安装器、npm、nvm、Volta、Scoop、WinGet）找；都找不到可以在 `config.bat` 里设 `CLAUDE_BIN`。
3. 到仓库的 [Releases](https://github.com/luckytiger125/Projector/releases) 页下载最新的 `Projector-server-vX.Y.Z.zip`，解压到任意文件夹（路径最好不带中文）。
4. 双击 `install.bat`：检查 Python 和 Claude Code、建好 `.venv` 装依赖，并引导你生成 `config.bat`（工作目录等）。
5. 双击 `start.bat`。第一次运行时 Windows 防火墙会弹窗，选择允许 **专用网络**（网页端用 TCP 8080，自动发现用 UDP 8090）。
6. 在台式机本机的浏览器打开 `http://localhost:8080`，**创建管理员账号**（只能在本机创建）。然后在“⚙ 管理 → 用户”里给同事建账号。
7. 台式机 `~/.claude/skills` 里原有的 skill 会对所有人生效。到“⚙ 管理 → 技能库”里一键导入技能库，再把原文件夹里的移走，之后就按分配生效。
8. 忘了管理员密码：在项目文件夹里运行 `.venv\Scripts\python server.py reset-password 用户名 新密码`。

从 v0.6 升级：覆盖文件后重启即可（数据库会自动加列和建表）。语音/板子功能已移除：原来的“板子”账号会被停用，语音会话保留为只读历史并归到第一个管理员名下，不能再继续对话；不会删除任何数据。

从 v0.7 升级到 v0.8：覆盖文件后重启即可。数据库改成了读写分开（一个人的慢查询不再让所有人等），`data` 文件夹里会多出 `center.db-wal` 和 `center.db-shm` 两个文件：**备份或搬家时要先停服务，再把 `center.db` 连同这两个文件一起拷**，只拷 `center.db` 可能丢最近的记录。

从 v0.5 升级：覆盖文件后重新双击 `install.bat`（要多装一个读 PDF 用的 `pypdf`），再启动。知识库文件夹会自动建好。

从 v0.4 及更早升级：原来放在 `data\workspaces` 里的工作区会在启动时自动搬到 `D:\Projector工作区`。

从 v0.2 升级：覆盖文件后重启。原来的访问密码（`CENTER_TOKEN`）不再使用，原来的会话会归到第一个管理员名下。

## 使用

- **同事**：装好桌面软件，打开后会自动找到局域网里的台式机，点一下，用管理员给的账号登录。浏览器也可以打开 `http://台式机名:8080`。
- **台式机本机**：浏览器打开 `http://localhost:8080`，或者装桌面软件并打开“服务端模式”。
- **手机**：个人菜单 → “在手机上打开”，扫码。

## 桌面软件（Windows）

`desktop/` 是一个用 Tauri 做的桌面壳子，窗口里就是上面的网页端，另外多了托盘图标和系统通知。

**下载安装**

1. 到仓库的 [Releases](https://github.com/luckytiger125/Projector/releases) 页，下载最新版本里的安装包，任选一个：
   - `Projector_x.x.x_x64-setup.exe`：推荐，装到当前用户下，不需要管理员权限
   - `Projector_x.x.x_x64_zh-CN.msi`：适合统一部署
2. 安装包没有签名，Windows 可能提示“已保护你的电脑”，点“更多信息” → “仍要运行”。
3. 第一次打开会自动查找局域网里的台式机，点一下就行；找不到时手动填 `http://台式机名:8080` 或 `http://台式机IP:8080`。之后打开软件直接进入登录页。

**使用**

- 关闭窗口不会退出，而是缩到右下角托盘；单击托盘图标显示/隐藏窗口。
- 托盘菜单：显示/隐藏窗口、重新加载、修改服务器地址、服务端模式、打开日志文件夹、退出。
- 有待确认的操作时，窗口不在前台也会弹 Windows 通知。

**服务端模式（只在台式机上打开）**

打开后不再需要 `start.bat`：软件开机自动启动（缩在托盘），在后台无窗口地运行 `python server.py`，进程崩溃会自动重启；托盘菜单里能看到进程是否在运行。

1. 先按上面“在台式机上安装”运行 `install.bat`，并确认双击 `start.bat` 能正常用（之后关掉 `start.bat` 的窗口，避免端口冲突）。
2. 在设置页勾选“服务端模式”，项目文件夹填本仓库所在的文件夹（`server.py` 和 `config.bat` 所在的位置）。也可以从托盘菜单勾选。
3. 环境变量读取 `config.bat` 里的 `set` 行；改了 `config.bat` 后在托盘里关掉再打开服务端模式即可生效。想指定 Python，可以在 `config.bat` 里加 `set "PYTHON=C:\路径\python.exe"`；项目文件夹里有 `.venv` 时会自动使用。
4. 进程输出写在日志文件夹的 `server.log` 里（托盘 → 打开日志文件夹）。

**自己构建**

推送到 `main` 且改动了 `desktop/` 时，GitHub Actions 会在 Windows 上自动构建安装包（在 Actions 页的 Artifacts 里）；也可以手动点 “Run workflow”。推送 `v` 开头的标签（比如 `git tag v0.1.1 && git push origin v0.1.1`）会自动发 Release。发版前记得同时改 `desktop/src-tauri/tauri.conf.json` 里的版本号。在 Mac 上开发调试：

```bash
cd desktop && npm install && npm run tauri dev
```

## 前端开发

网页端的源码在 `web/`（Vite + TypeScript + Preact），构建产物在 `static/app/`，**产物是提交在仓库里的**。所以台式机上不需要装 Node：下载发布包或者直接检出仓库，都能直接运行；运行时也不访问外网，字体只用系统自带的。

只有改网页端的人需要 Node（22 或更新）：

```bash
cd web
npm ci
npm run dev      # 开发：http://localhost:5173，接口转发到本机 8080 的服务端（用 PROJECTOR_PORT 换端口）
npm run check    # 类型检查 + 单元测试
npm run build    # 构建到 ../static/app
```

改了 `web/` 以后要重新 `npm run build`，把 `static/app/` 的变化和源码一起提交。CI 会重新构建一遍，产物和提交的不一致就不通过。文件名带内容哈希，首页不缓存，更新后刷新就是新版本。

- 目录：`web/src/features/` 按功能分（登录、外壳、值班板、对话、文件库、技能、账户、知识库、管理后台），`web/src/stores/` 是状态，`web/src/lib/` 是不依赖界面的工具，`web/src/styles/tokens.css` 是颜色、字号、间距等设计变量。
- 设计样稿在 `docs/design/`（静态网页，直接用浏览器打开 `index.html`），迁移方案在 `docs/plans/`。
- 页面有自己的网址（`/s/会话号`、`/files`、`/kb/notes`、`/admin/users` 等），刷新和前进后退都停在原处。

## 运行测试

```bash
python -m venv .venv
# Windows：.venv\Scripts\activate        macOS / Linux：source .venv/bin/activate
pip install -r requirements.txt -r requirements-dev.txt
python -m pytest -q
```

网页端的测试：`cd web && npm run check`。

测试用临时目录当数据、文件库、工作区和知识库，不会动 `data/` 和真实的 D 盘。

## 已知限制

- 接 DeepSeek 等第三方模型时，Claude Code 的 WebSearch（联网搜索）用不了。
- 所有人共用同一个 D 盘。给会话选好各自的工作文件夹能减少冲突，但两个人同时改同一个文件仍可能互相覆盖。
- 自动发现靠局域网广播，有的公司网络（访客 Wi-Fi、开了 AP 隔离、跨网段）会拦住，这时手动填地址。
